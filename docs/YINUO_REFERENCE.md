# 一诺合同（甄零）测试环境功能与界面梳理

> 环境：`oc-test.onecontract-cloud.com`（租户：灵宝黄金），2026-08-25 实地浏览梳理。
> 视角：业务方（业务员）、法务、管理员的流程/表单设置；全程只浏览未提交任何数据。
> 目的：作为 TuriX 合同管理系统 POC 的对标参考——**学它怎么把复杂能力装进简单的角色视图里**。

---

## 1. 总览：产品形态与设计理念

1. **角色决定界面**。右上角头像 → 角色切换：`系统管理员 / 法务 / 业务员 / 用章管理员 / 合同管理员`。切角色后左侧菜单完全重排：业务员只有 6 组菜单，系统管理员有 30+ 组。复杂度只暴露给需要的人。
2. **任务驱动的工作台**。所有角色进来先看"我该干什么"：任务中心一排生命周期计数器（待我协同 → 待提交审批 → 待申请用章 → 待我方签约 → 待对方签约 → 待上传归档扫描件 → 待归档 → 待反馈），点数字直达处理列表；另有 审批中心 四宫格（待我审批 / 我发起的 / 我参与的 / 抄送给我）和 续签/关闭提醒 卡片。
3. **文档为中心**。合同详情页主体就是合同正文（带二维码+水印的文档阅读器），业务字段收在右侧信息面板里——和我们目前"表单为主、正文在附件 Tab"正好相反。
4. **一切皆可配**：流程带版本可模拟，表单是"业务对象-字段-布局"三层模型，分类承载行为规则（关闭/水印/税目/编码）。这是它复杂度的来源，也是我们 POC 不必照抄的部分。

## 2. 角色 × 菜单对照

| 角色 | 左侧菜单（一级组） |
|---|---|
| **业务员** | 合同拟制 / 审批管理 / 合同拟制(查询) / 签署管理 / 归档管理 / 结束管理 |
| **法务** | 审批管理 / 模板管理 / 合同拟制 / 签署管理 / 事务履行(重大承诺) / 法务管理 |
| **系统管理员** | 30+ 组：HIPS-企业管理、系统管理、组织管理、开发管理、审批管理、基础设置、基础数据(管理)、模板管理、签署管理、归档管理、变更管理、结束管理、合同报表、审计管理、接口平台、调度平台… |
| 用章管理员 / 合同管理员 | （未深入）分别聚焦用印审批与合同域管理 |

审批管理组在普通角色下只有：`我的工作流(待办/已办/我发起/我参与) / 审批中心 / 个人自动处理规则`。

## 3. 业务方（业务员）视角

### 3.1 工作台
- 审批中心四宫格：待我审批 21 / 我发起的 238 / 我参与的 180 / 抄送给我 0，下方直接内嵌待办列表（流程名 / 描述 / 申请人和部门 / 任务开始时间），点行即办。
- 任务中心：按合同生命周期分桶计数（见 §1.2），每个桶点开是对应待处理合同清单。
- 快捷操作：合同起草 / 模板创建合同 / 上传创建合同 / 合同查询。
- 续签关闭提醒：临期合同"去续签"、应关闭合同"去关闭"。

### 3.2 融合起草中心（创建合同只有一个入口页，四条路径）
| 路径 | 说明 |
|---|---|
| **选择标准模板起草** | 从模板库选公司范本，"填空"生成完整合同 |
| **已有文件上传起草** | 本地 Word/PDF/Excel 原稿直接上传/拖拽，解析后继续编辑 |
| **复制已有合同** | 复用历史合同全部内容生成新草稿 |
| **合同续签** | 对到期/履约完毕合同一键生成续签版本 |

模板库界面：左侧分类树（每类挂模板数），卡片带"使用说明"，支持搜索/按合同性质筛选/批量选择；卡片悬停出 预览/使用。**模板本质是带变量的 Word 文档**（正文里 `${甲方-交易方名称}`、`${合同编码}` 等蓝色变量占位），起草=表单值回填变量。

### 3.3 合同台账（合同查询）
- 顶部：导入 / 导出下载 / 标准合同起草；快捷筛选 Tab：全部 / 已提交 / 协同中 / 草稿，以及 我审批的 / 我经办的 / 我发起的。
- 筛选链：合同流水号 / 合同状态 / 合同分类 / 相对方名称 / 金额 / 创建时间 / 其他来源单据，可"+"自定义并**保存筛选**。
- 两种视图：列表视图 / **进度视图**（按生命周期看）。
- 列：名称（**父子树**——变更/副本合同挂在原合同下）、编码、流水号、状态（新建/已签订/已归档/已关闭/已作废）、业务归属部门、负责人、分类、签订主体、相对方、创建人。

### 3.4 合同详情页（文档为中心）
- 顶部：名称+状态标签，阶段条 `已审批 → 已签署 → 归档中(0/2)`，附卡点提示（"归档扫描件待管理员修改，当前节点已停留20天"）。
- 左侧主体：合同正文阅读器（页码/缩放/全屏，正文带二维码与流水号水印），浮动工具：全览表单 / **文本对比**。
- 右侧信息面板 Tab：**基础信息**（交易方我方/对方及各自签署状态、编码/流水号/状态/性质/名称/签订部门…）/ 用章信息 / 交易信息 / **重大承诺**（可搜索的承诺清单，带"待履行"状态）。
- 最右竖排工具栏：指引 / 信息 / AI / 协同 / 模板 / **审批**（审批记录侧栏；无审批时显示"该合同的审批规则为自审批"）。

### 3.5 审批任务界面（审批中心）
- 左侧任务收件箱（我的待办/我参与的/我发起的），任务卡片直接显示关键上下文：签约方式=纸质签约、签署顺序=我方先用章、合同版本、发起人、已等待时长。
- 右侧任务详情五个 Tab：**摘要信息 / 签约流程 / 相关文件 / 审批记录 / 评论**。摘要=合同关键字段；相关文件=正文 PDF 可下载；审批记录=节点表（节点名/状态 已提交、已转交、已通过/处理人/到达时间/持续时长）。
- 底部动作条：**同意 / 拒绝 / 转交 / 抄送 / 加审 / 驳回**（拒绝≠驳回；旁有"按钮说明"）。

## 4. 法务视角

- 工作台与业务员同构（任务中心计数变为 待我协同/我已协同/待我审批），法务的日常主战场也是审批中心。
- 专属能力：
  - **模板管理**：维护公司范本库（业务员起草只能选用）。
  - **事务履行 → 重大承诺**：全公司重大承诺台账与履行跟踪（与详情页"重大承诺"Tab 呼应）。
  - **法务管理**（合同之外的法务域）：知识产权（商标/专利/软著/作品著作）、纠纷管理、案件管理、律师律所管理（律所/律师登记·变更·评价）、工商档案管理。
- 快捷操作多一个"模板查询"。

## 5. 管理员视角：流程与表单设置

### 5.1 流程设置（审批管理 → 工作流设置）
子菜单：`流程分类定义 / 流程定义 / 接口管理 / 全局配置 / 流程分类授权 / 审批链维护 / 业务单据流程配置`。

**流程定义列表**：左侧流程分类树（灵宝审批流程/分子公司合同审批/法务审批/外部流程模板…）；表格列 流程编码 / 名称 / 分类 / 来源(自定义) / 状态 / **当前生效版本 vs 最新版本**（有流程迭代到 24.0）/ 操作：**编辑流程图 / 模拟 / 发布**。流程按公司+场景细分（集团合同审批、各分/子公司合同审批、用章审批流按印章类型区分、合同关闭流程）。

**流程编辑器**（画布）：
- 节点面板：开始 / 结束 / **人工节点 / 子流程 / 智能节点 / 等待节点 / 抄送节点 / 填写节点**；网关：排他 / 排他收敛 / 并行；另有 通知、服务 节点组。
- 示例流程即客户需求场景：开始 → 排他网关按「印章类型」分支（合同专用章→人工审批；其他印章→智能节点）→ 收敛 → 结束。
- 右侧**全局属性**把行为做成开关：加签允许否 / 转交允许否 / 评论功能 / 流程撤回选项（始终允许 / 未审批过可撤回 / 不允许）/ 审批历史可见范围（全部/参与人/实际审批人）/ 申请人自动同意 / **拒绝后再次发起**（节点依次审批 or **跳转至被拒绝节点**）。
- 顶部：保存 / 校验并发布，带上次保存时间与"待发布"状态，左下角流程缩略图。

### 5.2 表单设置（基础设置 → 页面布局配置）：业务对象 → 字段 → 布局 三层
- **业务对象**树：合同管理（合同头 / 合同行 / 自定义合同行 / 合同正文 / 租赁条款 / 付款计划 / 收款计划 / 关联相对方 / 关联合同 / 关联附件 / 扩展信息 / 合同分类）、模板管理、签署管理、变更管理、结算管理、法务管理、相对方、合同归档、合同条款、合同结构化、物料管理、合同履行2.0、非合同用印、审核清单……
- **对象信息**：对象编码（OC_HCBM_CONTRACT）、是否模型化、布局类型（表单/查询表格）、启用分区/模板变量/水印二维码/智能提取/摘要等开关。
- **字段信息**：字段注册表——名称 / 编码 / 长度 / 字段分类（文本/文本域/金额/日期/下拉框/弹框）/ 字段类型（预定义 vs 自定义，可**添加字段**、同步新字段）/ 值集绑定（合同状态、经办人列表等）/ 智能提取映射 / **权限字段**标记 / 启用禁用。
- **布局**：同一对象可配多套表单布局（示例：灵宝黄金合同头、富金公司合同头、金额非必填版、合同全景图、新/旧拟制版），支持从既有布局复制、**按"生效条件"决定用哪套**（按公司/场景差异化表单），另有分区管理和查询表格布局。

### 5.3 合同分类 2.0（分类=行为配置）
分类树带 分类编码（LB/JSFW 这类简码——参与合同编号拼接）与收支类型（收入/支出/有收有支/无收无支）。编辑一个分类可配：创建合同时我方默认角色 / 适用场景 / **手动关闭条件、自动关闭时间、无有效期合同关闭设置** / 水印生成规则 / 二维码生成规则 / 印花税税目与税率 / 引用来源单据方式。

### 5.4 其他管理项（基础设置内，与客户需求直接对应）
`合同动态页签组成配置`（详情页 Tab 可配）、`文本水印配置`、`二维码配置`、`编码规则设置/维护`（对应客户需求 #11/#16）、`预警规则维护/管理`（对应 #9/#10 到期与归档提醒）、`审批中心配置 / 审批规则配置 / 审批矩阵规则维护`、`按钮权限规则 / 数据权限规则`、`规则引擎`、`要素库配置`（AI 要素提取）、`审核清单配置`、`智能摘要配置`。

## 6. 合同生命周期（从界面反推）

```
草稿(融合起草4路径) → 提交审批(可配审批流,加签/转交/加审/驳回) → 审批通过
  → [申请用章 → 用章审批(按印章类型分流)] → 我方签约 → 对方签约(纸质/电子E签宝)
  → 上传归档扫描件 → 归档确认 → 已归档 …… 期间/之后：变更(父子合同) / 续签 / 关闭 / 作废
状态标签：新建 / 已签订 / 已归档 / 已关闭 / 已作废；详情页阶段条：已审批→已签署→归档中(x/y)
```

每个阶段都变成工作台任务中心的一个"待XX"计数桶——**状态机即待办清单**。

## 7. 对 TuriX POC 的启示（怎么"变简单"）

**我们已经对齐的**：角色化瘦身菜单、任务驱动首页工作台、审批中心一级入口、模板范本方向（需求 #2）。

**值得抄的交互（低成本高感知）**：
1. **融合起草中心**：一页四入口（模板/上传/复制/续签），替代散落的"新建"按钮——我们现在只有"新建合同+上传正文"两步。
2. **详情页以正文为中心**：左文档右信息面板+顶部阶段条，比我们的五 Tab 更符合"看合同"的直觉（接 ONLYOFFICE 预览后可改造）。
3. **任务中心计数桶**：把生命周期状态直接变成首页可点的待办数字（我们工作台已有 4 卡，可扩成状态桶）。
4. **审批任务卡自带上下文**（签约方式/顺序/版本/等待时长）和 拒绝≠驳回 的动作语义。
5. **分类简码参与编码规则**（正是客户需求 #16 的产品化形态）。

**不必抄的重型能力**（一诺复杂度来源，POC 阶段明确不做）：业务对象/字段/布局三层可配 + 按条件选布局、规则引擎、审批矩阵、智能节点/AI 要素提取、法务扩展域（纠纷/案件/知产/律所）、多公司差异化流程矩阵。我们用"合同类型版本化表单 + SIMPLE 流程设计器"这一层抽象即可覆盖内部使用。
