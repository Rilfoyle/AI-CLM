## 固定账号与权限

| 视角 | 账号 | 用途 |
|---|---|---|
| 平台维护 | `admin / admin123` | 本地平台维护和默认流程负责人；不属于产品角色 |
| 业务经办人 | `business / admin123` | 起草、协同发起和提交 |
| 法务 | `legal / admin123` | 法务协同、审批和受控编辑 |
| 合同管理员 | `contractadmin / admin123` | G01-G10 治理、相对方导入、交接执行 |
| 系统管理员 | `systemadmin / admin123` | S01-S03 及受控沙箱运行，无合同正文权限 |

页面右上角身份菜单可在四个产品角色之间换发真实登录令牌，不使用前端伪造权限。业务、法务、合同管理员是显式 `ACTIVE` 组织+合同类型范围，系统管理员固定为 `NONE/NONE`，默认不能读取合同正文。

## 幂等基线

```powershell
pwsh -NoProfile -File scripts/seed-demo-data.ps1
```

脚本只接受固定 TuriX 租户和固定角色账号，并在发现账号漂移时停止，不会自动改写身份数据。首轮成功末行应为 `total=39, passed=39, failed=0`；紧接着再次执行应全部显示 `REUSE`，不得新增业务数据。默认基线为：

- 4 个已发布合同类型和 4 个独立 DOCX 模板：采购、销售、技术服务、保密协议；
- 6 个完全虚构的参与方；
- 6 份合同，分别覆盖草稿、法务协同、待法务审批、待合同管理员复核、驳回回草稿、审批完成；
- 1 条编号规则、1 条路由规则、1 版四角色权限政策和 4 条精确用户范围；
- 默认流程定义为 `法务(200002) -> 合同管理员(200003)`，合同管理员可在“审批管理 → 工作流设置 → 流程定义”中保存草稿或发布新版本；一期仍止于 `APPROVED`，无签署、归档和履约数据。

## 建议演示动线

1. 以 `systemadmin` 登录，从右上角身份菜单切换四个角色。
2. 业务经办人从“合同管理 → 合同拟制 → 合同起草”发起合同，再从“合同查询”查看 6 个阶段样本及相对方。
3. 法务查看 1 项待协同和 1 项待审批；在审批上下文确认按合同绑定版本展示“服务周期、验收里程碑”等扩展字段。法务工作台不显示业务草稿入口。
4. 合同管理员查看 1 项待复核，再进入“合同管理 → 审批管理 → 工作流设置 → 流程定义”（`/clm/approval-management/workflow-settings/process`），打开默认定义查看审批人、节点和合同字段条件；“保存草稿”不影响运行中审批，“保存并发布”会生成新流程版本。随后打开相邻的“业务单据流程配置”，确认合同类型、组织和金额选流入口。
5. 进入“合同管理 → 基础设置 → 合同分类”，在版本列表点击“版本/设计”：已发布版本只能预览；要修改表单，先“新建草稿版本”，再通过“页面布局配置”（`/clm/base-settings/page-layout`）设计字段并发布。“页面布局配置”只维护合同分类版本的合同表单，不是通用低代码页面或任意对象表单设计器。
6. 回到待复核任务查看相同动态字段；“审批中编辑合同”只有在当前节点政策允许 `customData` 或全部字段时可编辑，否则保持只读。
7. 系统管理员只显示审批管理、异常处理和系统管理，不显示合同拟制、模板管理、基础设置、基础数据或工作交接事项；直接读取合同详情应返回业务码 `403`。

## 自动化验收与清理

```bash
cd backend && mvn -pl yudao-module-clm test
cd ../frontend && pnpm ts:check && pnpm build:local
cd .. && pwsh -NoProfile -File scripts/seed-demo-data.ps1
pwsh -NoProfile -File scripts/e2e-yinuo-v1.ps1
```

演示数据脚本可重复执行；第二次运行必须全部显示 `REUSE`，不能新增合同、模板、流程版本或权限范围。恢复完全空业务基线时使用 `scripts/reset-turix-local.ps1`，不要用旧的 `seed-yinuo-v1-demo.ps1` 构造当前演示库。
