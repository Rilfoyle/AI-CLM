# MIF Build Plan

## Source Spec

- `docs/yinuo-replica/prd.md`：已确认的一诺复刻对象、流程、42 项功能和 20 个主页面信息架构。
- `docs/yinuo-replica/plan.md`：锁定决策、阶段门禁和模块进度。

## Planning Artifacts

- Active module：起草—协同/法务审查—合同审批。
- 第一版顺序：P0 核心闭环 → P0 治理支撑 → P1 增强与沙箱适配 → 干净演示基线。
- 不扩展：用章、签署、最终件、归档、履约、变更、续签、关闭和非合同通用低代码平台。按用户 2026-08-28 指令，合同域流程定义画布纳入第一版。
- 外部边界：AI 供应商与钉钉真实凭据未提供；先实现可替换适配层、持久化运行记录和本地沙箱，不发送真实合同到外部服务，也不宣称生产集成通过。
- 本轮状态：流程定义、业务单据流程配置、合同表单、审批态动态字段及 2026-08-29 菜单术语修订已完成。CLM 后端 `144/144`；演示数据首轮 `39/39`、第二轮全部 `REUSE`；专项 E2E `54/54` 且完成最终清理；前端检查、SQL13 幂等/结构检查和真实浏览器验收全部通过。

## Write Set

- 规划与契约：`docs/yinuo-replica/*`、必要的 `docs/CLM_*`、`docs/DELIVERY.md`、`docs/USER_GUIDE.md`。
- 数据库：只新增 `sql/08_*` 之后的幂等迁移；不重写或回滚现有 `sql/01`–`07`。
- 后端：`backend/yudao-module-clm/**`；仅复用 BPM 公共服务，不修改 Flowable 事实表和通用审批语义。
- 前端：`frontend/src/{api,views,components,store}/clm/**`、`frontend/src/views/Home/Index.vue`、CLM 隐藏路由与工作视图呈现所需文件；为复用合同字段条件，允许对 `frontend/src/components/SimpleProcessDesignerV2/**` 做最小、向后兼容的 props/inject 扩展。
- 演示与验收：`scripts/seed-demo-data.ps1`、`scripts/e2e-api.ps1`、`scripts/cleanup-e2e-data.ps1`、必要的第一版专项脚本和原创演示文档生成器。
- 不触碰现有用户未提交的 ONLYOFFICE/macOS 环境改动，除非第一版集成测试需要兼容性修正。

## Project Rules

- 合同是第一业务轴，不创建“合同申请”，不使用 `crm_contract`。
- `businessKey = workflow binding id`；Flowable 继续拥有流程、任务和正式审批意见。
- 文档版本不可覆盖，内容继续使用 CLM 私有 blob；禁止绕过合同 ACL 走匿名文件接口。
- 所有新增 DO 继承 `TenantBaseDO`，表包含 `tenant_id`，错误码使用 `1_070_*`，菜单 ID 使用 7000–7999。
- 列表数据权限在服务端 SQL 层过滤；系统管理员角色不自动获得合同正文权限。
- 修改 API 时同步契约；最终环境必须可演示、可验证、无 E2E 测试污染。

## Frontend

### Screens/components

- W01：角色工作台和真实工作项汇总。
- W02：仅标准模板和已有文件上传起草。
- W03：合同台账、范围/阶段筛选和已删除草稿恢复入口。
- W04：现有文档化详情升级为共享合同工作区，承载修订、承诺、AI、协同、提交与时间线。
- W05：协同队列和当前协同上下文。
- W06：合同审批唯一业务入口，区分 `taskId` 动作模式与 `contractId` 只读历史模式。
- G/S：复用统一治理列表、版本抽屉、运行报告和异常恢复模式，实现已纳入的治理及系统设置页面。
- G04（已实现）：提供“流程定义”列表和隐藏编辑路由，复用 SIMPLE 流程画布；“业务单据流程配置”单独管理选流条件。

### State

- 服务端为合同、修订、协同、审批和治理规则的事实源。
- 工作视图仅持久化当前呈现偏好；授权路由只注册一次，切换视图不删除路由或权限缓存。
- 筛选、页码、当前任务和历史模式保留在路由查询或页面状态中。

### Loading / empty / error / disabled

- 所有列表提供加载、空态、错误重试；所有动作提供成功结果和可恢复失败。
- P1 未形成可用沙箱前完全隐藏，不发布空菜单或装饰按钮。
- 已删除、已处理、已转交、无权、过期结论和重大重审均显示专用只读/失效状态。

### Responsive

- 桌面为完整工作端；W06 在窄屏只保留单任务摘要、正文只读和基本审批动作，在线改稿引导至桌面。

### Existing UI patterns reused

- `ContentWrap`、Element Plus 表单/表格/Tab/抽屉、`Pagination`、`v-hasPermi`、`useMessage`。
- W03 的 query 恢复、W04 的 `DocumentPreview`/ONLYOFFICE/文档版本、合同类型版本抽屉。
- BPM 时间线和意见只做展示，不直接承载合同审批 mutation。

### Surface coverage

- Entry：W01 快捷动作、待办卡、钉钉/站内深链。
- Primary：W04 合同工作区、W05 协同中心、W06 审批中心。
- Support：W03 恢复、G01–G10 治理、S01–S03 设置、异常与运行报告。
- Integration：CLM API、Flowable 公共服务、ONLYOFFICE、AI/钉钉适配层、菜单 SQL、种子与清理脚本。

## Backend

### API/command/data path

- 在现有 Contract/Document/WorkflowBinding 上补 ContractRevision、Commitment、CollaborationCase、审批任务—修订绑定。
- 已新增 CLM 流程定义治理门面，只允许查询、创建、修改和发布 `clm_contract_*` SIMPLE 模型；运行中实例不迁移，新提交使用最新激活定义。
- 提交时原子分配且永久绑定编号，解析唯一有效路由，冻结修订并创建审批业务单；重提沿用编号。
- 合同审批动作统一经过 CLM 门面，原子校验 assignee、节点编辑政策和决定修订，再调用 BPM 服务。
- 模板、编号、路由、权限、治理异常、相对方导入、AI、同步/消息运行记录使用独立领域表和 API。

### Validation

- 正文、参与方、重大承诺、模板/协同有效性、编号、唯一路由和审批人全部在服务端校验。
- 乐观并发使用 base revision/version；重复提交、重复审批和集成消息使用唯一键/幂等键。
- 重大编辑取消旧业务单并创建 `supersedesCaseId` 新业务单；非重大编辑在原实例继续并绑定决定修订。

### Permissions

- 租户、操作权限、合同关系/组织与类型范围、当前阶段和当前任务同时满足。
- G05 只写政策，S01 是具体用户范围唯一写入口；系统平台 ALL 不穿透合同域。

### Logging

- 追加式审计记录修订、协同、提交、审批决定、重审、恢复、授权、导入和集成运行；不记录密钥、token、合同正文或完整回调 URL。

### Mock boundary

- AI：本地确定性审查适配器，结果仍绑定精确修订并持久化；外部模型关闭。
- 钉钉：沙箱组织差异、SSO 映射和待办投递记录；真实调用关闭并明确显示未配置。
- 业务演示：空客户基线与演示基线分开执行；演示模板、参与方和合同均为原创虚构内容，只覆盖审批完成前状态，并以固定编码支持重建和核验。
- 身份切换：仅 local 环境允许在四个固定 TuriX 单角色账号间换发真实 token；默认关闭，禁止通用用户模拟和 break-glass 管理员切换。

## Acceptance

用户可以：

1. 从标准模板或已有文件创建草稿，在 W04 维护字段、参与方、承诺、正文和修订。
2. 非标合同发起法务协同，法务评论、改稿、要求修改或完成，旧结论随新修订过期。
3. 首次成功提交时获得唯一编号，审批人在 W06 对精确修订同意、退回或拒绝；撤回/重提沿用编号。
4. 审批中按节点授权编辑；非重大变化继续，重大变化取消旧单并启动新单，历史可追溯。
5. 合同管理员发布最小类型/模板/编号/业务单据流程配置/权限版本并处理阻断；系统管理员分配产品角色与数据范围。
6. 第一版在审批通过结束，不出现或生成签署、归档、履约任务。
7. 在头像菜单中连续切换业务、法务、合同管理员和系统管理员后，菜单、工作台、接口权限与 BPM 待办均属于当前真实账号；系统管理员仍不能读取合同正文。
8. 合同管理员可在“流程定义”中修改节点/审批人/条件并发布，“业务单据流程配置”可立即选择该定义；合同类型表单草稿发布后在新合同和审批上下文按绑定版本展示。
9. 审批上下文显示绑定合同类型版本的扩展字段；审批中编辑仅在节点政策允许 `customData` 或全部字段时可修改，否则保持只读且保存时不覆盖原值。
