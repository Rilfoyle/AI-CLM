# 一诺菜单与术语对齐修订

## 反馈分类

- 类型：`ia` + `copy`
- 是否改变核心产品方向：否。对象、权限边界、第一期终点和功能范围不变；只调整已实现能力的查找路径、命名和入口。
- 用户问题：当前“合同治理 → 规则设置 → 审批方案”是项目自造的技术分组，熟悉一诺的用户无法按“审批管理 → 工作流设置 → 流程定义”找到流程编辑。

## 证据边界

2026-08-29 对一诺测试租户进行了只读走查，确认以下当前可见原词和路径：

| 一诺可见模块 | 一诺可见子项 | 当前实现 | 本轮处理 |
|---|---|---|---|
| 合同拟制 | 合同起草、合同查询 | 起草中心、合同台账散落在根菜单 | 归入“合同拟制”，改为“合同起草 / 合同查询” |
| 审批管理 → 工作流设置 | 流程定义、业务单据流程配置 | 合同治理 → 规则设置 → 审批方案、审批路由 | 移除自造中间层，按一诺层级和原词重排 |
| 模板管理 | 模板管理 | 模板库藏在规则设置 | 提升为合同管理下的直接入口“模板管理” |
| 基础设置 | 合同分类、页面布局配置、编码规则设置、数据权限规则 | 合同类型、表单入口、编号规则、合同权限混在规则设置 | 归入“基础设置”；表单设计增加“页面布局配置”直达入口 |
| 基础数据 | 相对方维护 | 参与方 → 参与方目录 | 归入“基础数据”，页面命名“相对方信息” |
| 工作交接事项 | 经办人变更 | 异常处理 → 离职交接 | 独立归入“工作交接事项”，改名“经办人变更” |
| 系统管理 | 组织、用户、集成相关设置 | 系统设置 | 改名“系统管理”，保留本期已有三个真实页面 |

一诺还显示流程分类定义、接口管理、全局配置、流程分类授权、审批链维护、个人自动处理规则等入口，但本系统第一期没有对应真实能力，本轮不创建空菜单。签署、归档、履约继续按已锁定范围后置。

## Revision Map

| 用户反馈 | 类型 | 最小安全修改 | 影响文件/对象 | 验收 |
|---|---|---|---|---|
| 找不到流程编辑，“审批方案”与一诺叫法不一致 | IA / 文案 | 菜单改为“审批管理 → 工作流设置 → 流程定义”；列表与编辑页同步“流程编码、编辑流程图”等词汇 | `system_menu`、流程列表/编辑页、隐藏路由标题 | 合同管理员三次点击内到达流程定义；其他角色不获得流程配置权限 |
| 审批路由名称无法与一诺对应 | IA / 文案 | 改为“业务单据流程配置”，页内统一引用“流程定义” | `system_menu`、路由配置页 | 可从工作流设置进入，既有规则和 API 不变 |
| 合同拟制功能散落 | IA / 文案 | 新增“合同拟制”分组，归入“合同起草、合同查询、合同协同” | `system_menu`、角色父菜单授权、首页入口 | 业务/法务仅看到有权限的子项；起草入口可直接发现 |
| 模板、分类、表单、编码、权限难找 | IA / 文案 | 模板提升；新增“基础设置”；增加“页面布局配置”直达页；统一术语 | `system_menu`、相关 Vue 页、首页快捷入口 | 合同管理员能按一诺词汇定位；不增加第二份表单 schema |
| 参与方和交接使用项目术语 | IA / 文案 | “基础数据 → 相对方信息 / 相对方导入”；“工作交接事项 → 经办人变更” | `system_menu`、相关 Vue 页 | 已有数据、权限和服务端接口不变 |
| 旧书签可能因层级改变失效 | 兼容 | 为旧完整路径增加只跳转的隐藏别名，保留 query/hash | 静态兼容路由 | 旧地址刷新后跳到新地址，不产生第二个业务页面 |
| 本地重置仍按旧 58 项权限断言 | 测试/交付 | SQL13 纳入重置序列，按新菜单树更新精确菜单集合和数量断言 | SQL、PowerShell 重置/种子门禁 | SQL13 重复执行幂等；四角色菜单无越权、无孤儿节点 |

```text
合同管理
├─ 合同拟制

│  ├─ 合同查询
│  └─ 合同协同
├─ 审批管理
│  ├─ 审批中心
│  └─ 工作流设置
│     ├─ 流程定义
│     └─ 业务单据流程配置
├─ 模板管理
├─ 基础设置
│  ├─ 合同分类
│  ├─ 页面布局配置
│  ├─ 编码规则设置
│  └─ 数据权限规则
├─ 基础数据
│  ├─ 相对方信息
│  └─ 相对方导入
├─ 工作交接事项
│  └─ 经办人变更

   ├─ 产品角色与数据范围

   └─ 钉钉集成
```

## 保持不变

- API permission、后端 URL、数据库业务表和审批实例语义不改。
- 合同表单唯一事实源仍是合同分类版本；“页面布局配置”只是已有表单能力的直达门面。
- 流程定义发布后只影响新提交实例；运行中实例继续固定原定义版本。
- 系统管理员默认不获得合同正文和合同治理权限；业务/法务不因新增父菜单获得配置子项。

## 路由兼容约定

新菜单使用与业务模块一致的规范路径：

- `/clm/drafting/*`
- `/clm/approval-management/approval`
- `/clm/approval-management/workflow-settings/{process,routing}`
- `/clm/template`
- `/clm/base-settings/{contract-type,page-layout,numbering,permission}`
- `/clm/basic-data/{directory,import}`
- `/clm/handover/owner-change`
- `/clm/exceptions/{issues,reconciliation}`
- `/clm/system/*`

历史路径只保留为隐藏跳转别名，不出现在菜单中，也不承载第二份页面状态。
