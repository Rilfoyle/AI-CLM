# 客户需求（客户合同需求-原始.xlsx）与 POC 覆盖度分析

> 评估基准：2026-08-24 的 POC 现状（见 `docs/DELIVERY.md`）。
> 图例：✅ 已满足 ｜ 🟡 未做但容易（≤2 天/项，框架有现成能力）｜ 🟠 未做，中等工作量（3 天~1 周）｜ 🔴 有困难或需先做产品决策。
> 工作量为单人粗估，含联调不含需求澄清。

## 总览

18 条需求：**✅ 3 条已满足 ｜ 🟡 8 条容易补齐 ｜ 🟠 4 条中等 ｜ 🔴 3 条有困难/需决策**。
没有一条是当前架构做不了的；真正要提前拍板的只有 3 件事：**审批中可编辑（#12）**、**钉钉对接的账号与免登（#6/#7）**。

## 逐条分析

| # | 需求 | 优先级 | 状态 | 说明与实现路径 |
|---|---|---|---|---|
| 1 | 合同全生命周期留痕 | P1 | ✅（流程部分） | 已有追加式审计 `clm_audit_event`：创建/修改/删除/上传/下载/提审/审批结果/授权变更/在线编辑打开与保存，详情页「审计轨迹」Tab 可查，E2E 已验证。**归档环节的留痕**依赖 #3 归档功能补齐后自然覆盖。 |
| 2 | 合同范本库（标准模板） | P1 | 🟠 3~5 天 | 未做（README 原本就排在在线编辑验证之后）。方案：`clm_contract_template` + 版本表（照抄合同类型版本化的成熟模式），新建合同时"从模板创建正文 v1"= 复制模板文件为合同 v1。配合 ONLYOFFICE 在线编辑体验最佳，但纯上传模式也可用。 |
| 3 | 盖章后文本统一归档 | P1 | 🟡 1~2 天 | 后端已预留 `MANUAL_FINAL`（线下定稿回传）来源类型和 `EFFECTIVE(已生效)` 生命周期状态，差的是 UI 入口和"归档"动作：审批通过后详情页出【上传盖章件并归档】按钮 → 上传盖章 PDF/扫描件为新版本（标记 MANUAL_FINAL）→ 登记签署/生效日期 → 状态转「已生效」。与 #15 是同一件事。 |
| 4 | 模板更新后业务部门用最新版 | P1 | 🟠 随 #2 | 模板版本化后天然满足："从模板创建"永远取当前发布版；模板更新可配合站内信通知（同 #9 的通知机制）。 |
| 5 | 相对方主数据批量导入 | P1 | 🟡 0.5~1 天 | 未做。框架自带 Excel 导入组件（系统用户页就有现成的"下载模板+导入"模式，前后端都可照抄），给签约方加导入接口即可。 |
| 6 | 钉钉通讯录同步组织架构 | P1 | 🔴 3~7 天+外部依赖 | 框架只有钉钉扫码**登录**（justauth），**没有现成的组织架构同步**。需自研：调钉钉开放平台通讯录 API 定时同步部门/用户到 `system_dept/system_users`（增量+离职停用策略）。技术不复杂但有硬性外部依赖：企业钉钉的应用凭证、API 权限审批、同步冲突规则（本系统与钉钉谁是主数据）需要先定。 |
| 7 | 审批消息推送钉钉+跳转审批 | P1 | 🔴 3~7 天+外部依赖 | BPM 已有任务通知的挂点（站内信/短信模板机制现成），推钉钉工作通知/待办是新开发：调钉钉 todo API；**"跳转审批"是主要难点**——需要钉钉内免登（H5 微应用 + JSAPI 鉴权）直达流程详情页。建议第一期先做"消息+链接（手动登录）"，免登第二期做。依赖 #6 的用户与钉钉 userId 映射。 |
| 8 | 合同变更关联原合同、可追溯 | P1 | 🟠 2~3 天 | 未做（POC 范围外的"合同关系"）。方案：`clm_contract` 加 `source_contract_id + relation_type(变更/续签/补充)`，新建时可选"关联原合同"，详情页展示关联链并可跳原合同（原合同的版本与审批记录本就不可变，追溯天然成立）。 |
| 9 | 合同到期提醒经办人 | P1 | 🟡 1 天 | 未做。框架有 Quartz 定时任务 + 站内信，写一个 Job 扫 `expiry_date`（提前 N 天，N 可配）通知负责人即可；接上 #7 后可同时推钉钉。 |
| 10 | 签署后归档提醒 | P1 | 🟡 0.5 天（依赖 #3） | 同上：审批通过后若 X 天未上传归档件则提醒，逻辑挂在 #3 的归档状态上。 |
| 11 | 合同编码在**提交时**生成 | P1 | 🟡 <0.5 天 | 当前是创建草稿时生成。改为提审时生成（草稿期编码为空，表结构本就允许空），改一处服务端逻辑即可。 |
| 12 | 审批节点均可编辑合同表单 | P1 | 🔴 需先做产品决策，改造 1~2 周 | **与本 POC 的核心保障有冲突**：现在审批中合同被锁定、审批对象绑定准确版本+校验和（保证"审批的就是提交的"，这也是客户 #1 留痕/审计诉求的基础）。"节点可编辑"意味着审批过程中内容会漂移。可行方案：给审批节点配置**字段级编辑权限**，审批人改动＝生成新的表单快照/正文版本并记录"谁在哪个节点改了什么"，必要时可配置"改动后重走前序节点"。建议与客户确认：哪些字段可改、改后是否需要重新会签——确认后再动，不建议简单放开锁。 |
| 13 | 审批通过自动发起用章申请（可配审批流） | P1 | 🟠 3~5 天 | 未做，但架构已预留：`clm_workflow_binding.purpose` 支持一合同多流程。方案：新建用章申请对象 + 监听合同审批 APPROVED 自动创建并发起第二条 BPM 流程（`purpose=SEAL`，流程在设计器里可视化配置）。 |
| 14 | 审批记录展示该合同全部记录 | P2 | ✅ | 详情「审批记录」Tab 列出全部历史流程（含被驳回/取消的），驳回重提后旧记录完整保留（E2E 用例已验证），每条可跳流程详情看逐节点意见。 |
| 15 | 归档条件=任一方线下盖章后即可上传 | P1 | 🟡 随 #3 | 本 POC 不做电子签，归档本来就设计为"人工上传线下盖章件"，天然满足"任意一方盖章即可上传"；就差 #3 的 UI 入口。 |
| 16 | 合同编码拼接我方主体简称（多个用 / ） | P1 | 🟡 1 天 | 签约方表加"简称"字段（客户方案里的 partyShortName），编码生成器改为 `前缀+我方简称(/拼接)+日期+序号`；与 #11 一起做（都在编码生成器里）。 |
| 17 | 重大承诺未填不允许提交 | P2 | ✅（配置即可） | 服务端必填校验已强制（创建和**提交时**都校验，绕过前端也拦得住，E2E 已验证）。只需在对应合同类型的表单里把「重大承诺」字段设为必填。若要做成所有类型共有的核心字段，加一列也只是 🟡 级别。 |
| 18 | 客制化合同报表 | P2 | 🟠 视需求 | 未做，需求本身"根据灵宝需求出方案后开发"。可选：启用被隐藏的报表模块（积木报表，拖拽做报表）或直接写定制查询页。台账已支持多条件筛选；统计类报表等需求明确后估。 |

## 给排期的建议

1. **第一批（约 1 周，全是 🟡）**：#11+#16 编码规则 → #3+#15+#10 归档闭环 → #9 到期提醒 → #5 批量导入 → #17 配置重大承诺字段。做完后 P1 里只剩模板、变更、用章、钉钉、可编辑五件事。
2. **第二批（约 1.5~2 周）**：#2+#4 范本库、#8 合同变更、#13 自动用章申请。
3. **单独立项谈清楚再做**：#6/#7 钉钉对接（先解决企业凭证、主数据归属、免登范围）；#12 审批中可编辑（先和客户过字段清单与重审规则）。
4. #18 报表等需求明确后单独估。

> 另：客户需求隐含"在线看合同/模板"体验，对应本 POC 的 ONLYOFFICE 集成（代码已就绪，待有 Docker 的机器部署 Document Server 验收，见 `docs/CLM_ONLYOFFICE_SPEC.md` §6）。
